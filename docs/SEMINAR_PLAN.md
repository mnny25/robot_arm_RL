## 2. 슬라이드 구성 (본편 15장, 약 16분)

> 각 슬라이드: **제목 / 핵심 한 문장 / 내용 / 그림·자료 / 말할 것 / 시간**

### [도입] 1~4장 · 3분

**1. 표지** (10초)
- 제목: 강화학습 기반 로봇팔 Push 정책 학습 — 중간 보고
- 이름, 날짜

**2. 과제 목표와 진행 현황** (40초)
- 핵심: "시뮬레이션에서 Push 정책을 학습하고, 실물 로봇에 옮기는 것이 최종 목표"
- 내용: 최종 목표 한 줄 + Subtask 14개 진행표 (완료/진행/대기 색 구분)
- 그림: 진행표 (PROJECT_PLAN §1 표를 단순화)
- 말할 것: "오늘은 Subtask 9~11(보상, 학습, DR)을 중심으로 보고합니다."

**3. 시뮬레이션 환경** (50초)
- 핵심: "SO-101 로봇팔을 MuJoCo에 구성하고, 큐브를 목표까지 미는 과제를 정의"
- 내용: 장면 캡처 (로봇·테이블·큐브 4cm·목표 원 3cm), 제어 20Hz, 에피소드 10초
- 그림: 뷰어 스크린샷 1장
- 말할 것: 큐브 크기, 목표 반지름, 한 에피소드 길이

**4. MDP 설계** (1분 20초)
- 핵심: "정책은 31개 숫자를 보고 5개 관절을 조금씩 움직인다"
- 내용 (표 1개):
  - 행동: 관절 5개의 목표각 증분 (스텝당 최대 0.03 rad)
  - 관측: 관절 각도·속도, 팔→큐브, 큐브→목표 (상대 좌표), 큐브 자세·속도
  - 보상: 거리 페널티 + 진행 보상 + 성공 +10
- 말할 것: 상대 좌표를 쓴 이유(위치가 바뀌어도 같은 관계 → 일반화). 보상 세부는 백업 B1.

### [문제 발견과 개선] 5~7장 · 3분 30초

**5. 초기 결과의 문제점** (1분)
- 핵심: "성공률 91%였지만, 실제로는 세 가지 문제가 있었다"
- 내용:
  1. 큐브·목표 위치 고정 → 한 궤적만 외움
  2. 목표에 닿는 순간 성공 → 큐브를 **쳐서** 넣음 (최고속도 0.78 m/s)
  3. PPO·SAC 학습량 불일치, 시드 1개 → 공정한 비교 불가
- 그림: **영상 ①** (예전 정책이 큐브를 튕기는 장면)
- 말할 것: "숫자만 보면 잘 된 것 같았지만 동작을 보니 실물에선 안 될 방식이었습니다."

**6. 개선 1: 성공 조건과 보상 설계 원칙** (1분)
- 핵심: "목표 안에서 0.5초 멈춰야 성공으로 바꿨다"
- 내용: hold 판정 (원 안 + 속도 3cm/s 미만 + 연속 10스텝), 과속 페널티, push point 보상
- 원칙 한 줄: **"성공 전 스텝 보상은 항상 0 이하"** — 양수면 성공을 피하고 보상만 모으는 보상 해킹 발생
- 그림: 성공 판정 조건 도식 (원, 속도, 시간)

**7. 실험 1 결과: 시드에 따라 결과가 갈린다** (1분 30초)
- 핵심: "같은 설정도 시드에 따라 성공을 처음 발견하는 시점이 25만~115만 스텝으로 달랐다"
- 내용:
  - 50만 스텝: 시드에 따라 성공/실패 → 150만 스텝: 6개 모두 성공
  - 대조군(hold 없음)과 비교했더니 속도 감소는 hold 덕분이 **아니었다** (대조군도 0.27 m/s) → 결론 정정
- 그림: **F1** 시드별 학습 곡선 (fixed_hold, 6개 시드)
- 말할 것: "그래서 이후 모든 실험은 시드 3개, 같은 학습량, 대조군을 두고 비교했습니다." ← 발표 전체의 신뢰성 근거

### [일반화] 8~10장 · 3분 30초

**8. 개선 2: 위치 랜덤화 + 커리큘럼** (1분)
- 핵심: "정책은 학습 때 본 범위 안에서만 동작한다 → 범위를 넓히되 쉬운 것부터"
- 내용: 큐브 x 0.18~0.26, y ±0.06 / 목표 6~12cm, ±60° / 성공률 80% 넘을 때마다 범위 10% 확대
- 그림: 위에서 본 작업 영역 도식 (큐브 범위 박스, 목표 부채꼴) — `results/v2/workspace.png` 활용 가능
- 말할 것: in-distribution / out-of-distribution 개념 한 줄

**9. 실험 2: 일반화 결과** (1분)
- 핵심: "고정 위치로 학습하면 6%, 랜덤화로 학습하면 89~98%"
- 그림: **F2** 막대그래프 (fixed_hold vs rand_pp PPO vs rand_pp SAC, grid 성공률) + **영상 ②③** 나란히
- 말할 것: 평가 방법 — 학습 범위 안 27개 위치(grid) + 밖 5개(ood), 고정 세트로 반복 가능

**10. 실험 2: PPO vs SAC** (1분 30초)
- 핵심: "SAC는 절반의 경험으로 더 잘 배우고, 처음 보는 위치에도 강하다. 대신 시간은 6배"
- 내용 (표):

  | | PPO (300만) | SAC (150만) |
  |---|---|---|
  | 범위 안 | 0.89 ± 0.08 | **0.98 ± 0.02** |
  | 범위 밖 | 0.40 ± 0.16 | **0.73 ± 0.09** |
  | 학습 시간 | **약 45분** | 약 5시간 |

- 그림: **F3** 학습 곡선 (x축 스텝 / x축 시간, 두 패널)
- 말할 것: off-policy 데이터 재사용(업데이트 약 12만 vs 150만 회), 엔트로피 기반 탐색. **PPO는 기본 설정(엔트로피 보너스 0)** 이라는 한계도 같이 말하기.

### [강건성과 Sim-to-Real] 11~13장 · 4분

**11. 실험 3: DR을 다 넣었더니 학습이 안 됐다** (1분)
- 핵심: "마찰·질량·모터·지연·센서 노이즈를 전부 랜덤화하자 커리큘럼이 20~70%에서 멈췄다"
- 그림: **F4** 커리큘럼 range_scale 곡선 (rand_pp vs dr_full)
- 내용: 성공률 약 0.3, PPO·SAC 모두 → 알고리즘이 아니라 설정 문제
- (diag 결과가 나오면) 원인 한 줄 추가: "요소별로 하나씩 켜 본 결과, ○○이 주원인" — 세부는 백업 B4

**12. 민감도 분석: 무엇에 약한지 먼저 재자** (1분 30초)
- 핵심: "DR 없는 SAC는 이미 대부분 변화에 강하고, 약점은 높은 마찰뿐이었다"
- 그림: **F5** 민감도 히트맵 (행: 조건 / 열: PPO base, SAC base, PPO 마찰DR)
- 숫자:
  - SAC: kp ±40%, 지연 100ms, 질량 25~150g → 0.91 이상 유지 / **마찰 2.0 → 0.64**
  - PPO: 노이즈 3mm에서 0.56 (SAC 0.99) → **알고리즘만으로도 강건성이 크게 다르다**
  - PPO 마찰 DR: 마찰 2.0에서 0.22 → **0.44** (기본 조건 0.89 → 0.67) = DR의 트레이드오프
- 말할 것: "그래서 SAC에는 마찰 DR만 넣었습니다." → 결과는 13장 또는 이 슬라이드 하단 (11/17 결과 반영)

**13. Sim-to-Real 고려: 테이블 접촉** (1분 30초)
- 핵심: "성공률 100%였지만, 에피소드의 32% 동안 집게로 테이블을 약 15N으로 누르며 밀고 있었다"
- 그림: **영상 ④** (접촉점 표시) + **F6** 막대 (접촉 비율·접촉 힘, 개선 전/후)
- 내용: 접촉 스텝·접촉 힘 페널티 추가 → 접촉 비율 32% → **○○%** (11/17 결과), 성공률 ○○
- 말할 것: "실물 로봇은 아직 쓸 수 없어서, 실물에서 문제가 될 동작을 시뮬레이션에서 먼저 찾아 고치고 있습니다."

### [정리] 14~15장 · 2분

**14. 정리: 지금까지 배운 것** (1분)
1. RL 결과는 시드에 따라 크게 달라진다 → 시드 여러 개 + 대조군
2. 보상은 "성공 전 ≤ 0" 원칙, 숫자뿐 아니라 동작을 눈으로 확인
3. SAC는 샘플 효율·강건성, PPO는 시간 효율
4. DR은 민감도 분석 → 약점에만, 범위는 근거를 갖고

**15. 향후 계획** (1분)
- 실물 대비 보완: 큐브 회전·초기 자세 랜덤화, 손목 관절 고정, 실물 관측(카메라)만 쓰는 정책
- 엔드이펙터(IK) 제어 구현 (Subtask 4 잔여)
- 실물 사용 시: 지연·서보 응답·마찰 측정 → DR 범위 보정 → 배포 → Gap 분석 (Subtask 12~13)
- 그림: 간단한 타임라인

## 3. 남은 실험과 판단 기준

| 실험 | 상태 | 비교 대상 | 성공 기준 | 실패 시 |
|---|---|---|---|---|
| `phase3diag` (PPO, 시드 0) | 11/16 시작 | dr_full | 원인 요소 식별 | 백업 슬라이드로만 사용 |

| `rand_pp_contact_drf` (SAC ×3) | 11/16 시작 | rand_pp_contact | 마찰 1.5·2.0 성공률 상승 | "SAC는 마찰 DR 효과 제한적"을 결과로 보고 |

**평가 명령 (11/17)**
```bash
python -m push.evaluation.evaluate_v2 --runs "results/v2/rand_pp_sac_*" "results/v2/rand_pp_contact_sac_*" "results/v2/rand_pp_contact_drf_sac_*" --suite all --splits grid --out results/v2/eval_phase4.csv
python -m push.evaluation.table eval_phase4
python -m push.checks.table_contact results/v2/rand_pp_contact_sac_s0 results/v2/rand_pp_contact_sac_s1 results/v2/rand_pp_contact_sac_s2
python -m push.checks.status dr_
```

> 어떤 결과가 나와도 발표 흐름은 유지된다. 기대와 다른 결과는 "왜 그런지 분석 중"으로 정직하게 보고하는 것이 중간 보고에서 더 좋은 평가를 받는다.

## 7. 발표 원고 작성 요령

- 슬라이드마다 **첫 문장 = 핵심 한 문장**(§2)으로 시작하고, 근거 숫자 1~2개, 다음 슬라이드로 넘어가는 연결 문장 하나.
- 숫자는 소수점 둘째 자리까지만, 발표에서는 "98%", "6배"처럼 말하기 쉽게.
- 용어는 처음 나올 때 한 번 풀어 말하기: DR(물리값을 랜덤으로 바꾸며 학습), 커리큘럼(쉬운 것부터), OOD(학습 때 못 본 상황).
- 한계를 숨기지 않기: 시드 3개, PPO 미튜닝, 실물 미검증. 먼저 말하면 질문 공격이 약해진다.
- 연결 문장 예: 7→8 "시드와 대조군으로 비교 방법을 정한 뒤, 다음 문제인 일반화로 넘어갔습니다." / 10→11 "SAC를 기준으로 이제 실물 대비 강건성을 봤습니다."

## 8. 예상 질문과 답변 초안

| 질문 | 답변 요지 |
|---|---|
| 왜 SAC가 더 잘했나? PPO를 튜닝하면 달라지지 않나? | off-policy로 데이터를 재사용(업데이트 약 13배)하고, 엔트로피 최대화로 탐색을 유지해서. PPO는 엔트로피 보너스 0의 기본 설정이라 튜닝하면 차이가 줄 수 있음 → 향후 확인 과제로 인정 |
| 시드 3개로 충분한가? | 최소 기준. 표준편차를 함께 보고 했고, 결론이 바뀔 정도로 겹치는 경우(예: push point 효과)는 "차이 없음"으로 보고함 |
| DR 범위는 어떻게 정했나? | 처음엔 일반적인 값으로 넣었다가 학습이 실패함 → 민감도 분석으로 약점(마찰)만 선택. 실물 측정이 가능해지면 측정값 중심으로 재설정할 계획 |
| 전체 DR은 왜 실패했나? | diag 결과로 답변 (○○). 공통적으로 커리큘럼 기준(80%)이 DR 환경에 엄격해 범위가 넓어지지 못함 |
| 실물에서 큐브 위치는 어떻게 아나? | 카메라 + ArUco 마커로 위치 추정 계획. 이를 대비해 큐브 속도·자세를 빼고 위치 오차·지연을 넣은 관측으로도 학습 중 |
| 실물 배포는 언제? 시뮬과 다르면? | 실물 사용 일정 확인 중. 지연·서보 응답·마찰을 먼저 측정해 DR 범위를 보정하고, 같은 관측 코드로 시뮬·실물을 모두 돌릴 수 있게 설계 예정 |
| 관절 공간 액션을 쓴 이유? EE 제어와 비교했나? | 구현이 단순하고 모든 자세를 표현 가능. EE(IK) 제어는 Subtask 4 잔여로 구현 후 비교 예정 |
| 성공 후에는 로봇이 어떻게 되나? | 학습에서는 성공 시 종료라 성공 후 동작은 학습되지 않음 → 실물 실행 시 성공 판정에서 제어 정지 예정 |
| 큐브가 돌아가 있으면? | 현재 학습에는 회전이 없음(한계). 향후 계획에 포함 |
